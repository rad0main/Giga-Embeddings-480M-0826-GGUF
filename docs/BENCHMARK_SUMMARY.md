# Benchmark summary

Test bench (см. `embed_bench.py`) на встроенном наборе из 8 воспоминаний, 3 запросов,
3 пар похожих и 2 пар непохожих фраз. Время замерено на Windows 11, CPU only
(`-ngl 0`, `-t 4`, `--seed 42`), `llama-server` из локально собранного `llama.cpp`
(commit `5d5cb4c`).

## Помечено SKIPPED

- `rss_mb`: `wmic` отсутствует в Windows 11 24H2+; нельзя замерить RSS сервера
  встроенным инструментом. Альтернативы (Get-Process, psapi) не были включены в
  батарею, чтобы не тащить лишних зависимостей.

## Примечания к интерпретации

- **Pooling override.** На старте `llama-server` принудительно передаётся
  `--pooling mean --embd-normalize 2`, чтобы одинаково измерять обе модели.
  В GGUF giga хранит `qwen3.pooling_type = MEAN` (1), default — `LAST` (3).
  При `--pooling mean` обе фактически используют mean-pool, и сравнение
  валидно как «сравнение двух разных весов в одинаковом режиме», а не
  «сравнение разных режимов».
- **Det = −0.0** означает: косинус-дистанция между двумя запросами одного
  текста, детерминизм под `--seed 42`. Отрицательный ноль — численный артефакт
  float; фактически 0.
- **Recall@1 = 1.0 у giga** на обоих режимах (с/без инструкции) — на этом
  крошечном наборе модель попадает точно в цель. У default один запрос
  («механизм в мастерской») уходит в `m1` (Казлина вошла в мастерскую…)
  вместо `m7` (Шестерня повреждена) — релевантные документы похожи по
  поверхности, но не по сути.
- **Малый корпус.** 8 воспоминаний и 3 запроса — это sanity-check, а не
  полноценный retrieval-бенч. Recall@3 = 1.0 у обеих моделей следствие
  того, что gold-кандидаты почти всегда в топ-3 за счёт маленького корпуса.

